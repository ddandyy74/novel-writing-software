## 1. 架构概述

### 1.1 设计原则

| 原则 | 描述 |
|------|------|
| **离线优先** | 核心功能离线可用，云端同步作为增强 |
| **数据安全** | 本地加密存储，传输全程 HTTPS |
| **高性能** | 启动 ≤ 3s，保存 ≤ 100ms，撤销 ≤ 200ms |
| **可扩展** | 插件系统、AI 模型可替换 |
| **跨平台** | Windows/macOS/Web 统一架构 |

### 1.2 架构风格

采用**分层架构 + 微内核架构**：
- **分层架构**: 表现层、业务层、数据层、基础设施层
- **微内核架构**: 核心编辑器 + 可插拔功能模块（AI、多平台发布等）

## 3. 技术选型

### 3.1 技术栈决策

#### 前端技术栈

| 层级 | 技术选型 | 理由 | 备选方案 |
|------|----------|------|----------|
| **桌面框架** | Electron | 生态成熟、跨平台、开发效率高 | Tauri（更轻量） |
| **UI 框架** | React 18 | 组件化、生态丰富、TypeScript 支持好 | Vue 3 |
| **编辑器** | CodeMirror 6 | 性能优秀、可扩展性强 | Slate.js、Lexical |
| **状态管理** | Zustand | 轻量、简洁、TypeScript 友好 | Redux Toolkit |
| **样式方案** | Tailwind CSS | 快速开发、一致性好 | CSS Modules |
| **语言** | TypeScript | 类型安全、开发体验好 | - |

#### 后端技术栈（云端）

| 层级 | 技术选型 | 理由 | 备选方案 |
|------|----------|------|----------|
| **语言** | Node.js | 与前端统一、生态丰富 | Go（性能更好） |
| **Web 框架** | Fastify | 高性能、插件化 | Express |
| **数据库** | PostgreSQL | 功能强大、可靠性高 | MySQL |
| **缓存** | Redis | 高性能、支持多种数据结构 | - |
| **对象存储** | S3 兼容存储 | 成本低、可靠性高 | MinIO（自建） |

#### 本地存储

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| **数据库** | SQLite (better-sqlite3) | 轻量、无需服务器、性能好 |
| **加密** | SQLCipher / 自定义加密 | 数据安全 |

#### AI 技术栈

| 功能 | 技术选型 | 理由 |
|------|----------|------|
| **错别字检测** | 本地部署 BERT / 云端 API | 平衡准确率和成本 |
| **大纲生成** | GPT-4 / Claude API | 效果好、开发快 |
| **正文生成** | GPT-4 / Claude API | 效果好、上下文长 |
| **封面生成** | Stable Diffusion API | 效果好、可定制 |

### 3.2 技术选型决策记录 (ADR)

#### ADR-001: 选择 Electron 而非 Tauri

**状态**: 已接受

**背景**:
需要选择桌面应用框架，支持 Windows 和 macOS。

**决策**:
选择 Electron。

**理由**:
1. Electron 生态成熟，社区活跃
2. 与 React 生态无缝集成
3. 开发效率高，调试工具完善
4. 团队熟悉度高

**后果**:
- 优点: 开发快、生态好
- 缺点: 打包体积大（~150MB）

#### ADR-002: 选择 CodeMirror 6 而非 Slate.js

**状态**: 已接受

**背景**:
需要选择编辑器核心，支持富文本、撤销、性能要求。

**决策**:
选择 CodeMirror 6。

**理由**:
1. 性能优秀，支持大文件编辑
2. 撤销系统完善
3. 可扩展性强
4. 活跃维护

**后果**:
- 优点: 性能好、撤销完善
- 缺点: 学习曲线较陡

#### ADR-003: 选择 SQLite 作为本地存储

**状态**: 已接受

**背景**:
需要选择本地数据存储方案，支持离线使用。

**决策**:
选择 SQLite (better-sqlite3)。

**理由**:
1. 轻量级，无需独立服务器
2. 性能好，支持事务
3. 可靠性高，广泛使用
4. 支持加密 (SQLCipher)

**后果**:
- 优点: 轻量、可靠、可加密
- 缺点: 并发写入能力有限

#### ADR-004: 离线优先架构

**状态**: 已接受

**背景**:
网文作者经常在网络不稳定环境下写作，数据安全是核心需求。

**决策**:
采用离线优先架构，本地存储为主要数据源，云端同步为辅助。

**理由**:
1. 避免网络问题导致的数据丢失
2. 提升用户体验（无等待）
3. 降低云端成本

**后果**:
- 优点: 数据安全、体验好
- 缺点: 同步逻辑复杂

## 5. 关键设计决策

### 5.1 实时自动保存设计

```
用户输入
    │
    ▼
防抖处理 (300ms)
    │
    ▼
保存到撤销栈 (内存)
    │
    ▼
保存到本地 SQLite (异步)
    │
    ├───► 成功 → 更新保存状态提示
    │
    └───► 失败 → 重试队列
              │
              ▼
          用户提示
```

**关键技术点**:
1. **防抖**: 避免频繁写入，300ms 防抖
2. **异步写入**: 不阻塞主线程
3. **增量保存**: 仅保存变更部分
4. **失败重试**: 自动重试 + 用户提示

### 5.2 长文本撤销设计

```
撤销栈结构:
┌─────────────────────────────┐
│  操作记录 1                  │
│  - type: "insert"           │
│  - position: 100            │
│  - content: "插入的内容"     │
│  - timestamp: 1234567890    │
├─────────────────────────────┤
│  操作记录 2                  │
│  - type: "delete"           │
│  - position: 200            │
│  - content: "删除的内容"     │
│  - length: 50               │
│  - timestamp: 1234567891    │
├─────────────────────────────┤
│  ...                         │
├─────────────────────────────┤
│  操作记录 50                 │
└─────────────────────────────┘
```

**关键技术点**:
1. **操作记录**: 记录每个操作的详细信息
2. **内存限制**: 限制撤销栈大小（50 步）
3. **持久化**: 定期持久化到本地
4. **压缩策略**: 合并连续的小操作

### 5.3 本地-云端同步设计

```
同步流程:

本地修改
    │
    ▼
同步队列
    │
    ▼
网络检测
    │
    ├───► 在线
    │         │
    │         ▼
    │     拉取云端变更
    │         │
    │         ▼
    │     冲突检测
    │         │
    │         ├───► 无冲突 → 推送本地变更
    │         │
    │         └───► 有冲突 → 冲突解决
    │                   │
    │                   ├───► 自动合并
    │                   │
    │                   └───► 用户选择
    │
    └───► 离线 → 队列缓存，等待联网
```

**同步策略**:
1. **增量同步**: 仅同步变更部分
2. **版本号**: 使用版本号检测冲突
3. **时间戳**: 记录最后修改时间
4. **冲突解决**: 自动合并 + 用户选择

### 5.4 AI 功能集成设计

```
AI 服务架构:

客户端
    │
    ▼
AI 服务网关
    │
    ├───► 错别字检测服务 (本地 BERT / 云端 API)

    ├───► 大纲生成服务 (GPT-4 API)
```

## 7. 性能设计

### 7.1 性能目标

| 指标 | 目标 | 设计方案 |
|------|------|----------|
| 启动时间 | ≤ 3s | 懒加载、预编译、资源压缩 |
| 保存延迟 | ≤ 100ms | 防抖、异步写入、增量保存 |
| 撤销响应 | ≤ 200ms | 内存操作、压缩策略 |
| 编辑器输入 | ≤ 50ms | CodeMirror 优化、虚拟滚动 |

### 7.2 性能优化策略

**启动优化**:
1. 延迟加载非核心模块
2. 预编译关键资源
3. 使用 V8 快照

**编辑器优化**:
1. 虚拟滚动（长章节）
2. 增量渲染
3. Web Worker 处理大文件

**数据存储优化**:
1. 索引优化
2. 批量写入
3. 连接池
